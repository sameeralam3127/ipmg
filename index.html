Capabilities

Everything you need to keep a network honest

A modular, testable engine shared by the CLI and the dashboard — no agents to install, no cloud, no telemetry.

Parallel scanning

Up to 500 worker threads ping every target at once, so a full /24 finishes in seconds instead of minutes.

Subnet auto-discovery

--discover detects your local network and scans it — no need to type a CIDR block by hand.

Hostname resolution

Optional reverse-DNS (PTR) lookups with a thread-safe TTL cache, so repeat scans stay fast.

Change detection

Compare any two scans and see new, offline, moved, and slower hosts — with severity levels and CI-friendly exit codes.

Multi-format reports

Export to Excel, CSV, JSON, or a shareable Markdown report ready to drop into a ticket or incident timeline.

Local & hardened

No shell calls, every target validated, uploads capped, parameterized SQL, and the dashboard binds to localhost.

Quick start

One binary. Every workflow.

Point IPMG at a single host, a CIDR block, an IP range, or a file of targets. It does the right thing and stores every run in a local history you can compare later.

  • Flexible targets — 8.8.8.8, 10.0.0.0/24, 10.0.0.1-10.0.0.50, or an XLSX/CSV/TXT file.
  • Scheduled monitoring — --interval repeats the scan every N minutes.
  • Clean output — respects NO_COLOR, hides the progress bar when piped, ASCII fallback in dumb terminals.
# Scan your local subnet automatically
ipmg --discover

# A single host, a CIDR block, or a range
ipmg --input 8.8.8.8
ipmg --input 192.168.1.0/24
ipmg --input 10.0.0.1-10.0.0.50

# Targets from a file (xlsx, csv, txt, list)
ipmg --input targets.txt --threads 200
# Resolve hostnames and export CSV + Markdown
ipmg --input targets.txt --resolve --formats md csv

# All four report formats at once
ipmg --discover --formats xlsx csv json md

# Repeat every 5 minutes (scheduled monitoring)
ipmg --input targets.txt --interval 5
# Report what changed since the previous scan
ipmg --input targets.txt --compare

# List stored scans, then diff any two
ipmg history
ipmg diff 12 14

# Fail CI when anything changed (exit code 2)
ipmg diff --fail-on-change
# Start the local web dashboard + open the browser
ipmg dashboard

# Pick a port, keep it headless
ipmg dashboard --port 9000 --no-browser

# 'web' is an alias for 'dashboard'
ipmg web
Change detection

Know what moved between two scans

Every scan is stored in a local SQLite history. IPMG diffs any two runs and classifies each difference by severity — jitter is filtered out by dual latency thresholds.

ChangeSeverityMeaning
Host offlineCriticalReachable in the baseline, not reachable now
New hostWarningAn IP the baseline never saw
Host removedWarningAn IP the current scan no longer covers
IP address changedWarningA known hostname moved to a different IP
Service changedWarningStatus moved between failure modes (Timeout → Unreachable)
Host back onlineInfoRecovered since the baseline
Hostname changedInfoSame IP, different PTR record
Latency changedInfoLatency moved past both the absolute and percentage thresholds

Install

Up and running in one line

Ships as a pure-Python package. Pick whichever fits your setup.

pip

The standard way — from PyPI.

pip install ipmg

uv

Isolated global tool install.

uv tool install git+https://github.com/sameeralam3127/ipmg.git

curl

One-shot installer (adds uv if missing).

curl -sSL https://raw.githubusercontent.com/sameeralam3127/ipmg/main/install.sh | bash
Only scan networks you are authorized to scan. IPMG sends ICMP probes; unauthorized scanning may violate your organization's policies or the law.
Built to be safe

Security by default

IPMG is designed for authorized scanning, and the tool itself is hardened accordingly.

  • No shell calls. Pings run as a direct process invocation, and every target is validated as an IP address first.
  • Local only. The dashboard binds to 127.0.0.1 and serves everything locally — no CDN assets, no outbound requests.
  • Origin-checked sockets. A web page you visit can't connect to your local dashboard and read scan results.
  • Bounded inputs. Uploads are capped at 5 MB and one scan expands to at most 65,536 hosts.
  • Parameterized SQL. All database access binds values — never string-built queries.
  • CI in the loop. Bandit, pip-audit, and detect-secrets run on every push.
